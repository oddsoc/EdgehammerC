# EdgehammerC

**EdgehammerC** is an in-development C compiler inspired by *Writing a C Compiler* by Nora Sandler.

The compiler currently supports all C language features required to pass the book’s official test suite up through **chapter 13**, including every extra-credit feature.

The long-term vision for EdgehammerC is to serve as a playground for exploring language design. For now, I am focussed on working through the book.

Each chapter corresponds to a single commit in the repository, the only exception is chapters 6 and 7 — the test cases for chapter 7 passed as a side effect of changes I made for chapter 6 (oops!).  

To keep the history aligned with the book, commits are limited to chapter completions. Each commit will contain the changes needed to pass the chapter's test cases and will also incorporate any refactoring, bug fixes, and general improvements made since completing the previous chapter.

While the implementation mostly follows the book’s approach, some areas differ, EdgehammerC has a hand written tokeniser for example (for more on that see [performance](#-performance)).

---

## Current Limitations

No proper error handling yet — the compiler will panic on invalid input.
(This will be addressed after completing the book.)

The only platform currently supported is Linux on x64.

## Building

EdgehammerC targets stable Rust (edition **2024**) and depends only on the Rust standard library and unicode-ident crate. However, the preprocessor and tokeniser can take advantage of simd acceleration when built with the nightly Rust compiler - just enable the "simd" feature. 

To build without simd acceleration:

```bash
cargo build -r
```

or, with simd acceleration:

```bash
cargo +nightly build -r --features "simd"
```

## Performance

It's very premature to talk about performance but I found chapter 13 particularly hard and optimising the tokeniser was more fun! 🙂

As procrastination goes this was quite productive! I've measured the performance of the tokeniser (using Criterion) at **~595MiB/s** on the sqlite3.c amalgamation* with simd enabled, and **~490MiB/s** without. Tested on an Intel Core Ultra 7 165U, YMMV.

*preprocessed to remove # directives but with comments left in place.

To run the benchmark yourself, with simd:

```bash
cargo +nightly bench --features "simd" --bench tokeniser
```

or, without simd:

```bash
cargo bench --bench tokeniser
```

## Usage

Basic invocation (will produce a `some_program` executable in `some_folder` (can be overridden with `-o`):

```bash
./target/release/ehc some_folder/some_program.c
```

Assembly output can be generated by using `-S` flag and will create `some_program.s` in the current working directory.

Note: EdgehammerC calls out to cc to translate assembly into the final executable so you'll need to
ensure gcc or clang is also installed on your system.
